# STATUS.md — Project Audit Ledger

Single source of truth for **what is done, what is in progress, and whether quality gates truly passed**. Read this file first to understand project state; read PLAN.md Amendment A1 for what comes next.

## How this file is used

**By Claude Code (binding rules, per PLAN A1 §3):**
1. At the END of every session, before reporting a phase done: set the phase row's status, fill in its gate results, and update the demo and stats.js ledgers for everything touched.
2. Append-only. Never delete or rewrite a past row; corrections are new dated lines in the Notes column or the Session log.
3. A phase with any failing gate is marked `⚠ partial`, never `✅ done`, with the failure named. Only the maintainer may accept a partial phase.
4. Every deviation or limitation cites its DECISIONS.md ID.

**By the maintainer (5-minute audit per phase):**
1. Read the phase row below.
2. Open `/tests/index.html` in a browser — the green count must match the recorded count.
3. Open the touched chapter page — console must be clean; push each slider to min/max.
4. Spot-check one DECISIONS.md reference from the row.
5. Any mismatch → set the row to `🔁 reopened` (new line, don't erase) and file the issue.

**Status legend:** `⬜ not started` · `🔨 in progress` · `✅ done` · `⚠ partial` · `🔁 reopened`
